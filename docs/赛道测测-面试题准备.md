# 赛道测测 · 面试问答准备（Vibe Coding 项目）

适用场景：产品 / 前端 / 转码 / 运营转产品等面试，把本项目当「独立完成的 vibe coding 作品」。  
建议话术：**先讲问题与决策，再讲实现，最后讲迭代与取舍**。

线上演示：https://saidao-cece.vercel.app  

---

## 0. 30 秒电梯稿（背熟）

> 我做了一个叫「赛道测测」的互联网职业探索 H5。很多人测完性格不知道选什么岗，按专业推又会推歪。我用 Vite + React 做了纯前端流程：兴趣岛、MBTI、职场情景、已会工具多选、学历专业，本地算法算出人设和 Top6 岗位，还带卡点解法和海报分享。核心设计是**性格和工具主导排序，专业只做门槛**，并在用户反馈里迭代过匹配权重和交互坑。

---

## 1. 产品向高频题

### Q1：你为什么做这个？解决什么问题？

**答**：应届/转行找互联网工作时，「自我认知」和「具体岗位」之间缺一座桥。市面测试好玩但不落地，校招 JD 又太散。我想做一个 **7 分钟能跑完、结果能直接指导投递** 的轻产品。

### Q2：目标用户是谁？你怎么验证需求？

**答**：大学生和跨专业想进互联网的人。验证方式是快速上线 + 真实用户试测反馈，例如：
- Top 推荐一开始被吐槽「像只按专业索引」→ 我下调专业加成、加强性格/工具；
- 卡点手风琴互斥收起 → 改成可多开；
- 海报没反应 → 发现浏览器拦截静默下载，改成预览再下。

（强调：**用反馈驱动迭代**，不是一次做完美。）

### Q3：核心功能优先级怎么排？

**答**：P0 是完整路径（测→结果→可理解的推荐理由）；P1 是匹配可信度与分享；海报、彩蛋是增长向，但不能破坏主路径体验（例如海报叠字必须修）。

### Q4：你怎么定义「推荐准」？

**答**：不追求心理测量学意义上的绝对准，而追求 **用户体感一致**：人设、兴趣岛、工具、Top 岗位叙事不打架；同时避免明显离谱（文科无代码被推后端）。用「门槛 + 主排序」两层逻辑保证。

### Q5：如果只能保留一个差异点，是什么？

**答**：**专业不做唯一索引，工具与性格可校准现实可行性**。很多产品要么纯趣味性格，要么纯专业标签；我把两者解耦了。

### Q6：商业化怎么想？（若问）

**答**：当前是获客/作品向。可演进：校园渠道投放、岗位详情导流内容站、进阶报告付费。但本期刻意不做账号和付费，先把完成率和口碑做起来。

## 2. 算法 / 逻辑向

### Q7：匹配算法怎么做的？

**答**：
1. 把答题累加成用户向量（MBTI、Holland、价值观）；
2. 与岗位 ideal 向量做 **余弦相似度** 作主分；
3. 叠加背景目标、**工具加分（有上限）**、人设亲和；
4. 专业：对口轻加分；硬核工程岗对非对口强降权，有技术信号则轻降。

### Q8：为什么用余弦而不是简单加权总分？

**答**：岗位 ideal 是「画像形状」，余弦更关注方向是否像，而不是绝对分堆多高。实现简单、可解释，适合无后端的轻量方案。若以后有标注数据，可再上学习排序。

### Q9：工具多选会不会刷分？

**答**：会，所以做了 **tool boost 封顶**，并与「都还在学」互斥。工具是强信号但不能盖过性格主序——这是明确的产品约束。

### Q10：人设（Persona）和 Top6 会不会矛盾？

**答**：早期会。后来加人设亲和分，并在 Why 文案里同时写性格/兴趣/人设，降低「上面写逻辑实干家、下面全是运营岗」的违和感。

### Q11：兴趣岛和问卷里的兴趣题为什么去掉重复？

**答**：兴趣岛已经覆盖 Holland，再答一遍又长又噪声大。**信息架构上合并信号源**，缩短时长、提高完成率。

## 3. 前端 / 工程向

### Q12：技术栈与为什么这么选？

**答**：React 19 + TypeScript + Vite + Tailwind v4。选型理由：个人项目要 **快启、类型安全、部署简单**；无后端降低复杂度。海报用 `html2canvas`。

### Q13：状态和进度怎么存？

**答**：`App` 管页面状态；`localStorage` 持久化（key 随题库变更升版本，如 v5），支持续测。纯前端隐私友好，也限制了跨设备同步——这是取舍。

### Q14：海报功能踩过什么坑？

**答**：两个坑：
1. **异步后 `a.click()` 被浏览器当非用户手势拦截** → 改为生成后弹预览，用户再点下载；
2. **海报 DOM 常驻 `fixed + 负 z-index`，结果卡半透明导致叠字** → 改为仅生成时挂载 + 遮罩，截完卸载。

### Q15：多选题交互怎么设计？

**答**：单选保持「点完即跳」降低摩擦；工具题需要多选，所以改成勾选 +「选好了下一题」，并用互斥规则避免「都不会」和其他项同时选。

### Q16：如何保证移动端体验？

**答**：大圆角卡片、单列信息流、折叠优点/卡点减少首屏过载；弹层详情用底部/居中 sheet。仍可改进：更系统的触控热区与无障碍。

### Q17：部署方案？

**答**：Vercel 静态托管 + `vercel.json` SPA rewrite；国内访问不稳时可用 Netlify Drop 丢 `dist` zip。换电脑：`npm i && npm run build && vercel --prod` 或任意静态托管。

### Q18：如果让你加后端，你会加什么？

**答**：优先匿名埋点与题库配置下发；其次可选云端存进度。不做重账号，除非要做社区或报告付费。

## 4. 设计 / 体验向

### Q19：信息架构怎么避免结果页过长？

**答**：优点/卡点默认折叠；岗位先 Top6 卡片再详情；删掉用户觉得冗余的「通用预警雷达」。**同一屏只做一件认知任务。**

### Q20：视觉怎么定调？

**答**：海绿 + 珊瑚强调，避免「又一个紫渐变 AI 风」。展示字体用 Syne 增强品牌感；兴趣岛 emoji 降低测评压迫感。

## 5. 项目过程 / vibe coding 向（很重要）

### Q21：什么是你说的 vibe coding？你怎么和 AI 协作？

**答**：我负责 **问题定义、验收标准、用户反馈解读和产品决策**；AI 辅助生成组件、改权重、修 bug。我会 review 匹配逻辑和文案，用真机试路径，而不是无脑合并。

### Q22：你在项目里做了哪些「人」才该做的决策？

**答举例**：
- 专业权重先加强再回调（防止两种极端）；
- Top3 改 Top6；
- 增加工具题而不是继续堆性格题；
- 海报交互重做；
- 删雷达模块减负。

### Q23：最大的失败或返工是什么？

**答**：专业门槛一次加太猛，推荐「像按专业索引」；以及海报为了能截图把 DOM 放视口底层导致叠字。说明 **工程实现要服务体验，快捷方案要回归看真机。**

### Q24：如果再给你两周，你做什么？

**答**：埋点看完成率；结果页解释「为什么推荐你」更透明；岗位库与工具映射继续细化；分享图适配小红书尺寸。

### Q25：数据从哪来？有版权/准确性质疑怎么办？

**答**：岗位描述是综合互联网常见 JD 方向的结构化整理，薪资是区间示意非承诺；明确产品是 **探索工具不是录用保证**。人设/MBTI 是轻量启发式，不宣称临床级测评。

## 6. 可能的追问 + 短答

| 追问 | 短答 |
|------|------|
| 为什么是 25 个岗？ | 覆盖互联网常见方向够用；太多会选择困难，太少不准。 |
| 和霍兰德/盖洛普正版区别？ | 我们是应用层产品，借用经典维度做启发式，不替代正版量表。 |
| 如何防刷题乱点？ | 当前信任用户；可加一致性校验题或时长阈值，非本期重点。 |
| TypeScript 带来什么？ | 题库 flag、岗位 ideal、Answers 多选联合类型，减少改题库时的静默错误。 |
| 如何测试匹配？ | 构造典型画像（如国关+INTJ+无代码 / 设计+Figma）人工回归 Top 结果。 |

## 7. 演示路径建议（面试现场）

1. 打开线上 → 快速选岛（E/I/S 或你真实偏好）。  
2. 答题时强调 **工具多选**。  
3. 身份选一个跨专业组合，展示「门槛逻辑」。  
4. 结果页展开 1 条优点、1 条卡点 → 点开 Top 岗位详情。  
5. 点海报生成 → 说明曾经的坑与修复。  
6. 收尾回到产品决策句：性格+工具主序，专业门槛。

## 8. 你可主动展示的「亮点清单」

- 完整闭环产品，不是单页 demo  
- 有真实用户反馈驱动的权重与交互迭代  
- 匹配策略有清晰约束（封顶、门槛、主序）  
- 踩过浏览器安全策略与层叠上下文并修好  
- 可独立部署、代码结构清晰（data / lib / components）

祝面试顺利。用自己的话说，比背稿更重要。
